# 评分闭环

提交前核验比赛、权限、预算、剩余次数和安全评分窗口。明确的一次托管授权覆盖该比赛内预算允许的私有上传、提交和最终选择，不再逐版本询问；没有托管授权时按单步要求确认。公开发布、对外发文和额外个人信息披露仍须另行批准。

检查比赛提供的示例、提交格式和专用约束。CSV 可运行 `submission_check.py`，显式指定模式、ID 列、数值或标签预测列和需要的边界；分类概率可指定一组概率列检查范围与和。多 ID 列可重复传入。可变行数模式仅作通用格式检查，检测、分割、图结构、压缩包和可执行 agent 另做结构与运行检查。

检查通过后冻结文件哈希或 Notebook 的具体版本。按已安装官方工具的帮助构造命令，先核对参数再执行，不假设文件赛和代码赛使用同一入口。保存比赛、运行 ID、版本或文件哈希、时间、实际提交回执和之后的评分结果。

网络中断导致结果未知时，先查询平台历史确认是否已接收，不盲目重复提交。保存凭据之外的必要诊断信息。一次可见 Notebook 成功不等于隐藏评分成功，完成状态但分数为空也不能记为有效成绩。

代码赛失败时保留对应版本的可见日志、评分状态、错误和耗时。优先排查输入假设、依赖与路径、版本混淆、运行资源和输出格式。每次针对一个原因修复，并在模拟输入和平台可见运行中重验后再尝试。重复失败需改变诊断方法，预算不足或错误无法定位时报告具体阻塞；不能利用错误反馈探测隐藏标签。

提交后跟踪到取得有效分数、明确失败或具体外部阻塞。模拟赛分数会随对战变化，应记录观测时间和稳定性，不能将提交后的暂时排名写为定榜。
