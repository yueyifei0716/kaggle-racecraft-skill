# 参赛决策

选赛时比较任务兴趣、可用时间、独立样本量、指标稳定性、计算开销和允许使用的资源。给出推荐及其代价；不要用统一的样本量阈值评价所有任务。已有指定比赛就直接调查该比赛。

## 开始前形成事实表

从比赛页面核验名称、规则、截止时刻及其时区、队伍限制、提交类型、每日提交次数、评分方式和运行限制。记录查证日期和出处；不把旧比赛限制套到新比赛。按授权在平台接受规则；托管可委托 Agent 核验条款并自动加入，额外付费、公开或个人资料要求不在默认范围内。

检查现有文件再下载。理解标签如何产生、样本是否相关、公开与隐藏测试如何构建。缺失标签和负标签要区别处理。明确外部数据、模型权重、人工标注、联网以及共享的限制。

在 `competition.json` 中记录可用 GPU 小时、费用、截止时间、预留评分时间和目标。资源未知时先做小规模测量，不启动大任务。

## 路线不是“原创或抄作业”二选一

- **自行训练核心模型**：可使用现成架构、库和允许的预训练权重，通过比赛数据训练或微调。关键是掌握训练、划分和样本外预测，不要求发明新架构。
- **从公开方案出发**：先复现其版本，研究误差，再改模型、训练或推理流程。沿用别人已训练好的权重只调后处理，是这条路线的一种情况。

两条路线可以衔接。分别估算一次完整实验的训练、验证、排队、评分和排错时间，再估算可完成的有效实验数。只剩几天时，优先保障可提交的基线和足够的评分余量；时间充裕也不意味着自行训练必然划算。

将当前结果与公开可复现方案比较。如果核心差距无法通过外围改动弥补，应测量更大的改进方向；资源不足时坦陈限制，不靠连续微调维持进展的表象。

至少在新基线完成、公开方法出现重要变化、资源显著改变、比赛过半和进入最后安全提交窗口前重估路线。停止一个方向时记录依据，目标改变应遵循用户的选择。
